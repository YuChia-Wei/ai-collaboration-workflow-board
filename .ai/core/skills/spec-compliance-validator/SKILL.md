# Scoped specification compliance

Choose this skill for a complete validation plan, criterion-based semantic
assessment or scoped evidence-backed compliance conclusion. Improving an authoring
draft or designing GWT scenarios remains with its selected authoring/design owner;
those outputs do not require a compliance stage merely because this skill exists.

Select `plan-validation`, `review-semantics` or `assess-runtime` from
[compliance](references/compliance.md). They are instruction operations, useful
independently or together. No Python, configuration, mandatory authoring package,
source workflow or implementation pipeline is required to read these methods.

Use the [report outline](references/report-template.md) for four separate stages,
complete criteria, source/subject binding, evidence, exclusions and limits.
Select the actual format owner as an input: new CBF machine structure requires
its owning reader's real public result. This package provides no private parser,
schema, tool, persisted report format, store or machine template. Its selectable
package dependencies are empty; an unavailable selected reader is reported.

[Legacy intake](references/legacy-intake.md) preserves selected CBF/SWF semantics
and original bytes without pretending that machine compatibility exists.
[dotnet@0.1.0](profiles/dotnet.md) is an explicit opt-in instruction profile,
not an SDK, global target rule or automatic consequence of a .csproj filename.
Other target-owned profiles need explicit authority and evidence obligations.

Observed required contradiction means not-compliant; otherwise missing required
evidence, authority or nonempty scope means unavailable. Only complete required
coverage yields compliant-within-scope with exact subjects and exclusions.
A structural pass is never runtime acceptance or a universal correctness score.
