# dotnet@0.1.0 instruction profile

Select this profile explicitly for .NET runtime assessment. It is not a .NET SDK
version, executable tool, global distribution profile or automatic selection from
.cs/.csproj files. Without selection, .NET specialist runtime coverage is
unavailable while portable semantic review remains useful. Another runtime may
supply an explicit target-owned profile with authority/evidence obligations;
unknown or missing specialist coverage never becomes generic success.

Collect target-owned normative requirements, accepted architecture and actual
testing/analyzer decisions. Preserve the target's framework, ORM and bounded
context choices. No default xUnit, BDDfy, NSubstitute, BaseTestClass, DDD,
repository pattern, EF/Dapper choice or exception type is imposed here.

Require selected solution/project/test paths, actual SDK/runtime and runner/
package versions, target code/tests/config/dependency identities, permitted
execution environment and explicit restore/build/test authority and commands.
No executable project, SDK, known profile or required evidence means unavailable.
Never choose credentials, library versions, package installation, infrastructure
or restore actions solely to make this assessment proceed.

Map every selected command/input/handler signature, input field/type/requiredness,
PRE/POST/INV, error, domain event attribute and observable given/when/then condition
to implementation and actual assertions/runs at target-selected test levels.
Await event evidence when events apply. Keep style/analyzer findings separate
from behavioral acceptance. A build pass alone cannot establish a behavioral
criterion; a test name alone cannot establish a run. Preserve nonzero build/test
results, skipped tests, missing assertions and unreachable evidence.

Use only target-supplied argv, for example `<target-selected dotnet build argv>`
and `<target-selected dotnet test argv>`, with explicit working directory and
observation time. These placeholders are not runnable commands or authorization.
Assess supplied authentic runs unless separate target execution is authorized.

For applicable external authority, idempotency, timeout/retry, concurrency,
persistence, transaction, inbox/outbox and message-side-effect criteria, require
actual selected infrastructure/environment when the criterion calls for it.
Unit/mock/synthetic evidence never proves real database or message-flow behavior.
Do not standardize persistence or transaction ownership across bounded contexts.
Bind the frame/rules/code/tests/config/dependencies/profile/environment to the
same evidence subject; report contradictions first, then missing required
coverage, and only then a complete scoped conclusion.
