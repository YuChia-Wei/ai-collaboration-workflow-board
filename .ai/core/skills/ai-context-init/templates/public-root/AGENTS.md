## Scope And Precedence

- Follow user instructions and explicit approvals before repository guidance.
- A deeper AGENTS file takes precedence for its subtree within higher-level authority.
- Do not invent project truth, authorization, execution or validation. State
  material assumptions, conflicts and unresolved decisions.
- Make the smallest coherent change that satisfies accepted scope and observable
  completion criteria. Preserve unrelated changes and custom content.

## Progressive Context Loading

1. Start with the request, current Git/worktree state when available, this file and
   explicitly named artifacts.
2. When a skill applies and is available, select one owning route from the actual
   target runtime entries. Load only its entry and applicable references. Reload
   full source only for metadata, maintenance or discrepancy resolution.
3. Expand context only for the current task, phase or finding. Follow existing
   target workflow policy when applicable; a missing policy is not an invented gate.
4. Use the verified project index for navigation when needed. Load README,
   architecture, configuration and detailed rules only when relevant.
5. Keep project-specific facts outside reusable framework assets and verify
   material conclusions against current source and accepted project decisions.

## Execution And Validation

- Touch only required files and follow the target's branch/workflow rules.
- Continue reversible implementation and repair within authorized scope. Reuse
  existing approvals; ask for missing authority or material owner decisions.
- Implementation, push, PR, merge, Issue/Project updates, tags, release and
  publication are separate states unless authorized together.
- Resolve target commands, working directories and prerequisites before execution.
  Run required gates and the narrowest meaningful checks; broaden or repeat only
  for new changes, failures or unresolved concerns.
- Report failed, skipped, blocked and unrun checks truthfully. A discovered
  command or successful document parse is not evidence of product execution.
- Follow an existing target commit policy before committing. Do not manufacture
  policy paths, required services or approval records.
- Delegate only when authorized and available. Bound the task, ownership and
  evidence; retain one tracked writer per worktree and report actual invocations.
- Keep delegation within the user's selected model, reasoning and cost boundary.
  A role name is not permission to escalate. Disclose a needed escalation and
  obtain explicit authorization for a visible separate task before using it.

## CLI Execution Routing
